# Repeatable visual and workflow QA

Apply these inspection methods alongside the existing [quality contract](quality-review.md). They were useful in held-out pose checks, module sweeps and export/switching regressions. They do not establish a general success rate or justify new image transformations, different scoring thresholds or extra generation attempts.

1. **Freeze scope and keep evidence.** Save the immutable source, actual prompts/references, candidate bytes, attempted calls and permitted changes before evaluating results. Keep rejected, uncertain and failed candidates. A version, crop, registered image or reused output is not an independent generation. Do not transfer acceptance from raw art to a processed derivative.
2. **Inspect at useful scales.** Start with the full character at its intended display height. If no integration height is specified, inspect at 420 and 720 pixels and record those as diagnostic sizes, not a claim about the user's game. Then inspect the complete face, the target and still-protected components at native/detail scale. Review transparent edges on both light and dark backgrounds. Background-free images and same-size canvases do not prove preservation.
3. **Check framing independently.** Look at the head, torso and shoes for unintended scale/placement changes, and at newly extended hands, fingers, props and sleeves for clipping. Stable head/shoe alignment or a numerical match cannot establish that the new silhouette fits. Do not automatically register, resize, paste back a head or composite a limb as a QA repair. Those are separately authorized image operations with their own raw/derived provenance and visual checks.
4. **Inspect pairs when the intended use involves switching.** Compare the actual open/closed mouth or expression pair at the same display height and canvas-bottom anchor, then alternate the frames. Look for changes outside the requested region, especially eyes/brows, waist, skirt, shoe position and linework. Also compare the same pixel scale to reveal resolution-driven size changes. Layout scaling does not repair local drift. Deliberate pose or garment changes must be judged within their allowed scope, not by mouth-only invariants.
5. **Keep judgments distinct.** Record observed facts and uncertainty in the applicable contract/domain criteria. A body drift visible in a mouth-only edit is protection evidence; merely having a different resolution is a nonblocking technical warning. Save actual user feedback separately. Broad positive feedback does not supply a per-image acceptance count. An uninspected region remains uninspected; a loaded image or passing script is not a visual pass.
6. **Verify the delivered files.** After selection, check that PNG and ZIP bytes correspond to the chosen versions, their actual dimensions and warnings. Reopening a project must retain its history and selections; reselecting an older accepted version must preserve newer candidates. Export failure must not leave a misleading final package or replace an existing package. A final report should describe the current delivery outcome while retaining historical feedback verbatim.

Use the existing `preview`, anonymous `review-sheet`, `quality`, `fidelity`, `select`, `export` and `report` commands. Inspection evidence informs the already established gates; it does not add an extra user approval step or waive a failed criterion. Stop on a full pass or the recorded attempt limit. A static mouth asset may be useful without satisfying continuous-animation stability; record the intended use and evidence instead of claiming lip-sync support.

The repository's `tools/qa.py` automates immutable inspection snapshots and independent ZIP checks; `tools/qa_browser.py` exercises generated review HTML and switching controls. These are **developer tools**, not dependencies or commands in the installed plugin. For installed-plugin tasks, follow the same checks with the existing preview/review facilities and actual screenshots. The portable viewer exposes IDs and saved review status for regression work; use anonymous review packets for the formal visual assessment, and do not describe the developer viewer as blind evaluation.

The developer runner records file/workflow/browser results separately from visual quality (`not_assessed`). Synthetic fixtures are for workflow behavior only. A real-art inspection starts with blank observation fields and never writes scores, user feedback or selections into an input project. See the repository's `docs/qa.md` for repeatable commands and the regression matrix.

For mouth pairs intended for continuous switching, save a separate pair-level acceptance record bound to both image hashes and comparison screenshots. Inspect 420/720 at equal display height and equal pixel scale, native details, light/dark edges and alternating frames. Record mouth target, eyes/brows, head identity, waist/skirt, feet and framing independently. Unreviewed, uncertain or failed components prevent continuity acceptance; static image selection/export remains independent. Confirm a source image's expression and closed mouth explicitly before using it as a baseline. Never infer animation readiness from a static asset's accepted status. The developer `inspect` command creates a blank mouth-pair template; `audit-mouth` validates coverage, evidence and conclusions and produces a separate report. Installed-plugin work follows these observations with its existing preview facilities and reports the same distinction; no extra user approval is introduced.
